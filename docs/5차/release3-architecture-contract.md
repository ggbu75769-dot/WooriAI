# Release 3 Architecture and Migration Contract

Updated: 2026-07-15 (Asia/Seoul)

## Inventory conclusion

Present and reusable: Prisma/PostgreSQL persistence, rotating refresh-token families, Kakao OIDC prepare/exchange with state/nonce/redirect/replay validation, SecureStore, mobile expense outbox/conflict resolution, delta endpoint, consent snapshot, two-step settings flows, admin MFA/session/RBAC/CSRF, content revisions with `scheduledFor`, affiliate allowlist/redirect/click logging, strict analytics registry, catalog/payment Sprint 2 features, Android Pixel Lock tooling.

Absent and to be added: normalized OAuth identities/unlink, legal documents and consent events, durable privacy requests/export, owner transfer, Redis worker/outbox/DLQ, scheduled publisher/cleanup handlers, remote config, notification state/delivery, product-link health, operations consoles, shared tracing/redaction/metrics, real production builds and release configuration gates.

## Process topology

```text
Mobile / Public Next routes / Admin Next routes
                    |
                 HTTPS
                    |
                 Nest API
             /        |        \
      PostgreSQL    Redis     ObjectStorageAdapter
           |           |
       JobOutbox --> publisher --> queue
                                  |
                                Worker
          privacy/export/unlink/import/notification/publish/health/cleanup/integrity
```

PostgreSQL is authoritative. Redis is an at-least-once transport/rate-limit store and must never become the only copy of business or privacy state.

## Additive migration sequence

1. `000012_release3_foundation`: enums/tables/columns for OAuth identities, legal/consent evidence, privacy requests/events, outbox/DLQ, config, notifications, link health, content sources/tags, presets and compatibility snapshots.
2. backfill OAuth identities from legacy user provider columns and initialize safe config/default consent metadata without inventing production legal approval.
3. deploy dual-read/dual-write services and new APIs; legacy endpoints continue to work.
4. deploy outbox publisher and worker. Business transactions create outbox rows in the same Prisma transaction.
5. enable low-risk topics in non-production; dangerous remote flags remain OFF until dependencies and drills pass.
6. validate old-to-new upgrade and clean install, then only in a future approved release deprecate legacy identity/payment fields.

Existing migrations `000001`–`000011` are immutable.

## Auth contract

- Mobile generates PKCE verifier/challenge and uses server-issued state/nonce transaction context.
- The server stores only nonce hash and exact allowed redirect, atomically consumes the transaction, fixes allowed JWT algorithms, and verifies issuer/audience/expiry/subject.
- Provider tokens/codes are never persisted or logged. Provider email never causes automatic account merge.
- `OAuthIdentity(provider, providerSubject)` is unique and is the login lookup source after backfill; legacy user provider fields are compatibility fallback only.
- production without complete provider configuration fails closed. `/auth/oauth-login` remains inaccessible outside dev/test.
- deletion queues provider unlink through a retry-safe adapter and records safe state, never provider credentials.

## Privacy contract

- `ConsentEvent` is append-only and references the exact `LegalDocument` content hash. The current `Consent` snapshot changes in the same transaction.
- account deletion creates a durable request, immediately revokes sessions/devices/access, then outboxes purge and unlink work.
- every privacy state transition is validated and appended as an event. Retries are idempotent; terminal processor failures reach DLQ rather than being silently completed.
- shared households require owner transfer and anonymize the departed actor; sole households are purge candidates under the approved policy.
- export is generated by a worker through an object-storage adapter, encrypted by a production-configured key, exposed by a short-lived signed URL, audited, then purged.

## Queue/outbox contract

- publisher polls visible unpublished rows in batches with concurrency-safe claims, uses `(topic,dedupeKey)` uniqueness, and marks publication only after queue acceptance.
- every handler receives schema version, trace ID and dedupe key; it records an idempotent result before acknowledging.
- retryable vs terminal errors are explicit. Maximum-attempt failures become redacted DLQ records with audited admin retry/cancel.
- graceful shutdown stops taking new jobs and waits for bounded in-flight completion.

## Remote config / notification fail-safe

- config is versioned and returned with ETag. Mobile stores last-known-good config.
- failure disables analytics, affiliate, import, push and unavailable auth providers; core expense read/write remains available unless maintenance/read-only mode explicitly applies.
- notification marketing defaults OFF, device tokens are removed at logout/deletion, quiet hours use `Asia/Seoul`, and provider absence keeps notification dispatch OFF.

## Release and rollback

- API, worker, and admin images are separate immutable artifacts. Mobile Expo export and Android AAB are explicit build jobs.
- production gate rejects placeholder package/version/operator URLs, mock adapters, missing signing/env, unsafe flag defaults, migration/contract drift, and analytics opt-in defaults.
- database rollback is forward-fix: take a pre-migration snapshot, deploy additive schema first, and keep old code readable against the new schema.
- application rollback returns to the previous immutable artifact while new nullable/defaulted columns remain.
- after restore, run integrity checks and replay completed/pending privacy deletions before reopening writes.
