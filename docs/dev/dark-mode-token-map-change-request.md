- 상태: **승인 대기 — 승인 전에는 효력 없음.** 이 문서는 `docs/dev/do-not-change.md`의 원칙

- 날짜: 2026-09-06

## 0. 왜 변경 요청인가 — 그리고 왜 이번 사이클은 NO-GO인가

다크 모드 팔레트 도입은 DNC-017이 잠근 토큰에 **모드별 두 번째 값**을 세우는 일이라, 개정 이력에
남지 않으면 "임의 교체"다. 그래서 코드보다 문서가 먼저 선다. 동시에 라운드 101 정찰 S2는 이번
사이클 반입을 **NO-GO**로 판정했고, 이 문서는 그 판정을 뒤집지 않는다 — 선행 조건(§4) 중 하나인
"대응표 변경 요청을 승인 대기 상태로 세우기"만 이번 라운드의 몫이다.

S2 실측(이 문서 작성 시 재검증한 것은 재검증 값을 함께 적는다):

1. **`theme.colors` 참조 922개 / 46파일** — 재실측 일치.
   자(needle): `apps/mobile`의 `app/`+`src/`에서 `*.test.ts(x)` 제외 `.ts/.tsx`의 `theme.colors.`
   출현 수 / 파일 수. 테스트까지 넣으면 1,109개 / 82파일이다(둘 다 2026-09-06 워킹트리).
2. **참조의 43%가 모듈 평가 시점에 동결** — S2 실측 인용(모듈 상단 `StyleSheet.create`/상수로
   값이 import 시점에 복사되는 자리). 이 문서는 이 비율을 재실측하지 않았다 — 그 전수 분류는
   T2 트랙(§4)의 첫 걸음이고, 여기서는 "테마 객체를 런타임에 갈아 끼우는 것만으로는 화면이
   따라오지 않는다"는 판정 근거로만 인용한다.
3. **a11y 계약이 `theme.colors.` 철자와 결합** — 재확인. `apps/mobile/src/a11y-contract.test.ts:117`의
   `lowContrastCoralTextPattern`이 `color: theme.colors.(mainCoral|subCoral|peach|coral[50..600])`
   철자를 정규식으로 물고, 파일 전체에서 `theme.colors` 철자를 무는 줄이 50줄이다. ⚠️ 이 계약은
   다크에서 **뒤집힌다**: 라이트에서 금지된 coral[300]·coral[400]이 다크에서는 정확히 써야 하는
   계단이다(§4의 이관 계획 참고).
4. **렌더 자동 검증층 부재** — 재확인(`useColorScheme`/`darkColors`/`colorSchemes` 흔적 0건).
   다크 렌더를 기계로 확인하는 자리가 오늘 저장소에 없다.
5. **팔레트 승인 근거 부재** — 다크 팔레트는 c20deeb 같은 승인 캡처 계보가 없다. 이 문서의 후보값은
   전부 **제안**이며, 승인(사용자 지시 + 실기기 실측)이 근거를 만들기 전에는 DNC-017 개정 요건을
   충족하지 못한다.

## 1. 원칙 (S2 제안 채택)

1. **웜 다크 브라운 캔버스** — 순검정(#000/#121212 계열 뉴트럴)이 아니라 라이트의 크림 웜톤을
   뒤집은 브라운 캔버스: bg `#17120F`, surface `#221B17` 계열. 브랜드의 온기를 다크에서도 유지한다.
2. **코럴 스케일 역방향** — 스케일 값 자체(coral 50~900)는 명도 사다리로서 그대로 두고, **역할이
   무는 계단을 뒤집는다**: 텍스트/아이콘 코럴은 600→400(`#F98060`), 소형 코럴 텍스트는
   700→300(`#FFA58A`), 틴트 표면은 50/100→다크 코럴 틴트(신규 값).
3. **CTA 채움은 coral 600 유지** — 채움 `#C94627` + 흰 라벨은 다크 캔버스 위에서도 4.78:1로 AA를
   넘는다(부록 A). 브랜드의 얼굴인 주 버튼 색은 두 모드에서 같다.
4. **Secondary 밝힘** — `#267A68` → `#4FB39B`(다크 캔버스 위 7.31:1).
5. **텍스트/상태색은 전부 밝힌 웜 변형** — 아래 대응표의 모든 텍스트 용법 후보는 bg·surface 위
   4.5:1(AA 본문) 이상을 실계산으로 확인했다(부록 A에 계산 과정).

S2가 실계산으로 든 여섯 쌍은 이 문서의 후보값으로 전부 **정확히 재현·재검증**됐다:

## 3. 미결 칸 — 디자인 판단 필요 (후보값 + 대비 계산만 제시)

아래 21건은 **이 문서가 확정 후보로 밀지 않는다.** 색이 정보를 나르는 자리(카테고리)거나 승인
캡처의 인상을 직접 만드는 자리(presentation)라, 수치만으로 정할 수 없고 디자인 판단(실기기에서
형광 부상·채도 과열 여부 확인)이 필요하다.

## 부록 A. WCAG 대비 계산 과정 (근사 없이 직접 계산)

이 문서의 모든 대비 수치는 WCAG 2.x 정의를 그대로 계산한 값이다(소수 셋째 자리에서 반올림).

1. 각 채널 `c ∈ {R,G,B}`(0~255)를 `v = c/255`로 정규화한 뒤 선형화:
   `v ≤ 0.04045`이면 `v' = v/12.92`, 아니면 `v' = ((v+0.055)/1.055)^2.4`
2. 상대 휘도: `L = 0.2126·R' + 0.7152·G' + 0.0722·B'`
3. 대비: `CR = (L밝 + 0.05) / (L어둡 + 0.05)`

검산 예 1 — textPrimary `#F3EDE9` vs bg `#17120F` (S2 쌍 #1):

- `#F3EDE9` = (243, 237, 233) → 선형 (0.896269, 0.846873, 0.814847) → L₁ = 0.855063
- `#17120F` = (23, 18, 15) → 선형 (0.008568, 0.006049, 0.004777) → L₂ = 0.006493
- CR = (0.855063 + 0.05) / (0.006493 + 0.05) = 0.905063 / 0.056493 = **16.02**

검산 예 2 — textInverse `#FFFFFF` vs CTA `#C94627` (S2 쌍 #5):

- `#FFFFFF` → L₁ = 1.000000
- `#C94627` = (201, 70, 39) → 선형 (0.584078, 0.061246, 0.020289) → L₂ = 0.169443
- CR = 1.05 / 0.219443 = **4.78**

같은 절차로 계산에 쓴 주요 휘도값: `#221B17` L=0.011858 · `#F98060` L=0.364226 ·
`#4FB39B` L=0.362690 · `#C4B8B0` L=0.491513. 나머지 쌍은 동일 공식의 스크립트 일괄 계산이며,
표의 어떤 수치도 근사·추정이 아니다.
