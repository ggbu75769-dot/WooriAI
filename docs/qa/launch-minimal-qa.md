# 출시 전 필수 30분 QA 시트 (실기기 · 최소)

작성: 2026-09-02 (출시 준비 트랙 LP-E)

> ⚠️ **이 문서는 추출본이다.** 판정·결과 기입의 단일 소스는 언제나
> `docs/qa/runtime-verification-required.md`(실기기 142행)와
> `docs/qa/accessibility-offline-checklist.md`(C-3 판정)이며, 이 시트는 그 표에서
> **출시 전에 반드시 밟아야 하는 최소 집합만** 뽑아 30분 안에 돌 수 있게 순서를 붙인 것이다.
> 원문은 한 글자도 고치지 않았고, 이 시트에 체크한 결과는 **원문 체크표의 해당 행에 옮겨 적는다**
> (특히 C-3은 접근성 체크표의 "확인일 + 기기 + 결과" 칸이 정본이다).

## 준비물 (시작 전에 한 번)

- [ ] 안드로이드 실기기 1대 (에뮬레이터 불가 항목 없음 — 실기기 권장)
- [ ] **프로덕션 빌드 1개**: `EXPO_PUBLIC_TEST_LOGIN=0` + 카카오 env 주입
      (`pnpm android:build-apk` 류 — env 없이 gradle 직접 실행 금지). 항목 1·2가 같은 빌드를 쓴다.
- [ ] 버릴 실제 카카오 계정 1개 (핵심 루프 가입용 — #97 경고: 재시도하면 같은 이름의 아이가 둘 남는다)
- [ ] API 서버 켜짐 + 어드민 접속 가능 (항목 5)
- [ ] TalkBack 켜는 법 숙지 (설정 > 접근성 > TalkBack — 항목 4)

총 예상 소요: **약 29분** (아래 항목별 표기 합).

---

## 항목 1 — `EXPO_PUBLIC_TEST_LOGIN=0` 빌드 첫 화면 (≈3분)

원문: runtime-verification-required.md §1-1 **#55** (일부 #102 ⓒ)

- **준비물**: 위 프로덕션 빌드 설치 직후, 로그아웃(첫 실행) 상태.
- **걸음**: 앱 실행 → 스플래시 → 로그인 화면(AUTH-001)을 읽는다.
- **기대 결과**:
  - [ ] 부제가 "카카오로 로그인하면 아이 정보부터 차근차근 시작해요."
  - [ ] 버튼이 "카카오로 시작하기"
  - [ ] 테스트 로그인 버튼 · "실제 카카오 로그인이 아니에요" 배지 · 꼬리말이 **한 개도 없다**

## 항목 2 — 핵심 루프 1회 완주 (≈10분)

원문: §1 #1~#4 · §1-1 #97(가입) · #28/#135(구매 확인) · #7/#8(준비템·링크)

- **준비물**: 항목 1과 같은 빌드, 버릴 카카오 계정, 네트워크 연결.
  온보딩 동의 단계에서 **분석(통계) 동의를 켠다** — 항목 5의 재료가 된다.
- **걸음** (순서대로, 각 화면 통과가 곧 체크):
  - [ ] ① 카카오로 가입 (약관·개인정보 동의 + **분석 동의 켬**) → 온보딩 진입
  - [ ] ② 온보딩 완주 (아이 정보 → … → 완료) → 홈 착지, 아이 이름·시기 배지 표시
  - [ ] ③ 빠른 지출 기록 1건 저장 → 홈 총액·이번 달 사용액 **즉시 반영**
  - [ ] ④ 준비템 탭 → 지금 시기 목록 표시 → 항목 상세 열기 (가격·제휴 고지 문구 표시 확인)
  - [ ] ⑤ 구매 링크 클릭 → **외부 브라우저**가 열린다 (막다른 Alert가 아니다)
  - [ ] ⑥ 3분 안에 앱으로 복귀 → "샀나요?" 구매 확인 카드가 선다 → 기록을 남기면 카드가 사라지고 다시 묻지 않는다
  - [ ] ⑦ 리포트 탭 → 월간/누적 금액이 홈과 **같은 금액**

## 항목 3 — 오프라인 기록 → 재동기화 (≈4분)

원문: §1-1 #38(홈 대기 고지) · §1 #12(재시작 유지)

- **준비물**: 항목 2의 계정 그대로.
- **걸음**:
  - [ ] ① 비행기 모드 켬 → 지출 2건 기록 → 저장이 **거부되지 않고 대기로** 남는다
  - [ ] ② 홈 누적 카드에 "동기화 대기 중인 기록 N건" 한 줄이 뜬다
  - [ ] ③ 앱 완전 종료 → 재실행 → 대기 기록이 살아 있다 (persist)
  - [ ] ④ 비행기 모드 해제 → 대기 줄이 사라지고 총액·리포트에 금액이 **정확히** 반영된다

## 항목 4 — C-3 잠금 오버레이 TalkBack 투과 (≈7분) 🔒 **릴리즈 전 필수**

원문: **접근성 체크표 C-3**(판정 정본) = runtime-verification-required.md **#26** ·
표 전체에서 "릴리즈 전 필수"가 명시된 **유일한** 항목 (2026-09-01 기준 스물아홉 라운드 연속 미확인).

- **준비물**: 지출 기록이 있는 로그인 계정 (항목 2~3의 계정 그대로), TalkBack.
- **걸음**:
  - [ ] ① 설정에서 앱 잠금(PIN)을 켠다
  - [ ] ② 앱을 백그라운드로 보냈다가 복귀(또는 재실행) → 잠금 오버레이가 뜬다
  - [ ] ③ TalkBack을 켜고 잠금 화면을 **끝까지 스와이프 탐색**한다
  - [ ] ④ (부정 조건) 잠금을 끈 뒤 같은 화면들을 훑어 낭독이 종전과 같은지 본다
- **기대 결과**:
  - [ ] 잠금 중 **뒤쪽 금액·품목·아이 이름이 한 건도 낭독되지 않는다** (PIN 입력 UI만 들린다)
  - [ ] 잠금 미사용 상태의 낭독은 종전과 완전히 같다 (방패가 평소에 무언가를 지우지 않는다)
- **결과 기입**: `docs/qa/accessibility-offline-checklist.md` C-3 행과 "수동 증거" 절에
  **확인일 + 기기명 + 결과**를 적는다 — 이 시트의 체크만으로는 그 줄이 닫히지 않는다.

## 항목 5 — 분석 동의 수신 (≈5분)

원문: §1-1 **#34**

- **준비물**: 항목 2에서 분석 동의를 켠 채 온보딩을 밟았을 것, 어드민 접속.
- **걸음**:
  - [ ] ① 어드민 > 분석에서 온보딩 **단계별 진입 수**와 퍼널의 온보딩 4단 접두가 보인다
  - [ ] ② (부정 조건 — 여유가 있으면) 동의를 끈 상태로 온보딩을 다시 밟아도 이벤트가 **한 건도** 늘지 않는다

## 나머지는 출시 후 순차

위 다섯 묶음이 덮는 원문 행을 뺀 나머지 실기기 행(137행)은 **출시를 막지 않는다** — 출시 후
라운드에서 순차로 밟는다. 목록·판정·행별 근거는 전부 원문이 진다:

- `docs/qa/runtime-verification-required.md` — §0 실행 표면 분류(실기기 142 · 브라우저 20 ·
  서버 9 · 작업 1), §0-1의 ⛔ **#103 스토어 자산 재캡처**(제출 차단 — QA가 아니라 **작업**이라
  이 시트 밖이다. 절차: `docs/store/submission-checklist.md` §0.1), §1·§1-1 행 전체.
- `docs/qa/accessibility-offline-checklist.md` — 접근성·오프라인 체크표와 수동 증거 절.

이 시트에는 어떤 행의 판정도 **살지 않는다**. 여기 체크는 진행 메모이고, 기록은 원문에 남긴다.
