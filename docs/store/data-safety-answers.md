# Play Console 데이터 안전(Data Safety) 설문 답안지 (STORE-101)

> 상태: 제출용 초안 v1 (2026-08-20). **모든 답은 코드로 확인한 실제 구현 기준.**
> 근거 파일: `apps/api/prisma/schema.prisma`, `apps/api/src/settings/settings.controller.ts`,
> `apps/api/src/households/household-runtime.service.ts`, `apps/api/src/onboarding/onboarding-store.service.ts`,
> `apps/mobile/src/analytics/flag.ts`, `packages/contracts/src/analytics.ts`,
> `apps/api/src/items-commerce/affiliate-link-guard.util.ts`,
> `apps/mobile/android/.../xml/network_security_config.xml`.
> `infra/legal/privacy-policy.html`과 항목이 1:1로 일치해야 한다 — 한쪽 수정 시 반드시 동기화.

## A. 개요 문항

| 콘솔 문항 | 답 | 근거 |
|---|---|---|
| 앱이 필수 사용자 데이터를 수집하거나 공유하나요? | **수집: 예 / 공유: 아니요** | 아래 항목별 표 참조. 제3자에게 사용자 데이터를 전송하는 코드 경로 없음 |
| 수집된 모든 사용자 데이터가 전송 중 암호화되나요? | **예** | Android `network_security_config.xml`: `cleartextTrafficPermitted="false"` (예외는 로컬 개발 호스트 `localhost`/`10.0.2.2`뿐 — 릴리즈 트래픽은 전부 HTTPS) |
| 사용자가 데이터 삭제를 요청할 수 있는 방법을 제공하나요? | **예** | 앱 내 설정 > 약관 및 개인정보(SET-003/004): 계정 삭제·아이 프로필 삭제·가구 탈퇴 2단계 플로우 (`app/settings/privacy.tsx` → `POST /settings/account/delete-confirm` 등) |

### ⚠ 계정 삭제 웹 URL 요구사항 (미충족 — 후속 티켓 필요)

Play 정책상 **계정 생성이 가능한 앱은 "웹에서 접근 가능한 계정 삭제 요청 URL"을
Data Safety 섹션에 반드시 입력**해야 한다(2024년부터 시행). 현재 앱 내 삭제 플로우는
완비되어 있으나 **웹 삭제(또는 삭제 요청 접수) 페이지는 구현되어 있지 않다.**

- 제안: 후속 티켓 `STORE-1xx` — 정적 페이지 1장(삭제 절차 안내 + 이메일 접수 안내)로도
  요건 충족 가능. `infra/legal/`에 `account-deletion.html` 추가 후 약관·처리방침과 같은
  도메인에 호스팅.
- 임시 대응: 페이지 준비 전에는 설문 제출이 막히거나 반려될 수 있으므로 **Day 3 제출 전
  필수 선행 작업**으로 취급할 것.

## B. 데이터 유형별 답안

표기: 수집 = 앱이 기기에서 서버로 전송해 보관 / 공유 = 제3자에게 전송.
"임시 처리"가 아닌 모든 항목은 계정과 함께 저장됨.

### B-1. 개인 정보 (Personal info)

| 세부 유형 | 수집 | 공유 | 필수/선택 | 목적 | 근거 |
|---|---|---|---|---|---|
| 이름 | **예** | 아니요 | 필수(카카오 프로필 닉네임 자동 수신) | 앱 기능(가족 구성원 표시) | `User.displayName` ← 카카오 OIDC `claims.nickname` (`kakao-auth.service.ts`) |
| 이메일 주소 | **예** | 아니요 | **선택**(카카오 계정에 이메일이 있고 제공에 동의한 경우만) | 앱 기능, 계정 관리 | `User.email` nullable ← `claims.email ?? null` |
| 사용자 ID | **예** | 아니요 | 필수 | 앱 기능, 계정 관리 | `User.providerUserId`(카카오 계정 식별자) + 내부 UUID |
| 전화번호 | **아니요** | — | — | — | 스키마에 `phone` 컬럼은 있으나 이를 채우는 코드 경로 없음(카카오 로그인은 닉네임·이메일만 매핑) — 수집 아님 |
| 주소, 인종·정치 성향 등 | 아니요 | — | — | — | 해당 없음 |

### B-2. 재무 정보 (Financial info)

| 세부 유형 | 수집 | 공유 | 필수/선택 | 목적 | 근거 |
|---|---|---|---|---|---|
| 기타 재무 정보 | **예** | 아니요 | 필수(핵심 기능) | 앱 기능(지출 기록·예산·리포트) | `Expense`(금액·날짜·품목명·판매처·메모·결제수단), `Budget`. 사용자가 직접 입력하거나 엑셀/CSV 가져오기로 승인한 내역만 저장(DNC-012) |
| 결제 정보/신용 정보 | **아니요** | — | — | — | 결제 기능·카드 연동 없음. 인앱결제 없음 |

### B-3. 앱 활동 (App activity)

| 세부 유형 | 수집 | 공유 | 필수/선택 | 목적 | 근거 |
|---|---|---|---|---|---|
| 앱 상호작용 | **예(선택)** | 아니요 | **선택 — 옵트인, 기본 OFF** | 분석 | 설정 화면 "통계 수집 동의(선택)" 토글이 유일한 스위치(`analytics/flag.ts`: `enabled: false` 기본). 동의 전에는 이벤트가 큐잉조차 되지 않음. 서버 저장 시 사용자 ID는 HMAC-SHA256 익명화(`analytics-anon.util.ts`), payload는 enum/불리언/정수만 허용(금액은 구간 버킷) — PII 린트가 CI에서 강제(`packages/contracts/src/analytics.ts`) |

### B-4. 기기 또는 기타 ID (Device or other IDs)

| 세부 유형 | 수집 | 공유 | 필수/선택 | 목적 | 근거 |
|---|---|---|---|---|---|
| 기기 또는 기타 ID | **예** | 아니요 | 선택(알림 사용 시) | 앱 기능(푸시 알림) | `UserDevice.pushToken`(+ 해시된 기기 ID, 앱/OS 버전). `notificationEnabled` 기본 false |

### B-5. 기타 정보 — **자녀 관련 정보의 분류 결정**

| 세부 유형 | 수집 | 공유 | 필수/선택 | 목적 | 근거 |
|---|---|---|---|---|---|
| 기타 정보 | **예** | 아니요 | 필수(핵심 기능) | 앱 기능(시기 계산·준비템 추천·리포트) | `Child`: 태명/애칭(nickname), 생년월일 또는 출산예정일, 성별(선택) — **보호자가 직접 입력** |

**분류 결정 이유(제출 시 참고):** 이 앱의 사용자는 보호자이며 아동이 아니다. 자녀 데이터는
아동 본인에게서 수집하는 것이 아니라 성인 사용자가 입력하는 콘텐츠이므로, Play의
"어린이 대상 앱" 데이터 규정이 아닌 일반 데이터 항목으로 신고한다. 실명이 아닌
태명/애칭 사용을 UI에서 유도한다. 다만 생년월일+애칭 조합은 민감할 수 있어
처리방침에 별도 항목으로 명시했다(`infra/legal/privacy-policy.html` §5).

### B-6. 수집하지 않는 항목 (전부 "아니요"로 답)

위치, 사진·동영상(스키마에 `profileImageUrl`/`Attachment`가 있으나 **업로드 코드 경로가
없어 실제 수집되지 않음** — 기능 추가 시 설문 갱신 필요), 오디오, 파일·문서(엑셀
가져오기는 사용자가 명시적으로 선택한 파일을 지출 내역 파싱 목적에만 사용 — 콘솔
정의상 "파일 및 문서" 수집으로 신고할지 애매하나, 파싱 후 지출 레코드로만 저장되므로
**"파일 및 문서: 수집 예(선택, 앱 기능 목적)"로 보수적으로 신고 권장**), 캘린더, 연락처,
문자, 통화기록, 건강·피트니스, 검색 기록, 설치된 앱 목록.

### B-7. 경계 항목(내부 기록용 — 콘솔 신고 여부 판단 메모)

- **IP 주소**: 원본 IP는 저장하지 않음. 동의 기록·감사 로그·제휴 클릭에 **솔트된
  SHA-256 해시**만 저장(`hashClickIp`, `AFFILIATE_CLICK_IP_SALT`). 일방향 가명처리이므로
  콘솔 항목으로 별도 신고하지 않되, 처리방침에는 투명하게 기재함.
- **User-Agent 문자열**: 동의/제휴 클릭 기록에 저장. 기기 모델 수준 정보로, "기기 또는
  기타 ID" 신고에 포괄되는 것으로 처리.

## C. 공유(제3자 전송) — 전 항목 "아니요"인 근거

- 광고 SDK, 외부 분석 SDK(Firebase/GA/Amplitude 등) 미포함 — 분석은 자체 API로만 전송.
- **제휴 링크 클릭**: 쿠팡/네이버로 이동 시 전달되는 `subId`는 **클릭마다 새로 생성되는
  무작위 UUID**로, 사용자·아이 식별자에서 파생되지 않음(`redirect.controller.ts`:
  "subId is a self-generated uuid ... never derived from any user/child identifier").
  비로그인 리다이렉트 경로는 userId 자체를 기록하지 않음. → 제3자에 사용자 데이터
  공유 없음.
- 처리 위탁(호스팅 사업자의 서버 운영)은 콘솔 정의상 "공유"가 아닌 서비스 제공자
  처리로, 공유 아니요 유지. 위탁 내용은 처리방침 §7에 기재.

## D. 광고 여부

- **광고 없음**으로 신고(광고 SDK·배너·전면광고 없음).
- ⚠ 유의: `ProductLink.isSponsored`/`sponsorLabel`(스폰서 상품 표시, DNC-011) 기능이
  스키마에 존재한다. **실제로 스폰서(광고성) 상품 노출을 시작하면** Play의 광고 정의
  (네이티브/스폰서 콘텐츠 포함)에 해당할 수 있으므로 그 시점에 "광고 포함" 재신고 검토.
  현재 출시 시점에는 스폰서 상품 미운영 전제.

## E. 데이터 처리 관련 기타 문항

| 문항 | 답 | 근거 |
|---|---|---|
| 데이터가 사용자를 위해 처리되는 주된 방식 | 계정 기반 저장(서버) + 기기 내 오프라인 캐시(SQLite) 후 동기화 | `apps/mobile/src/offline/` |
| 삭제 요청 시 데이터 처리 | 앱 내 삭제 플로우로 처리. 계정 삭제 시 즉시 탈퇴 처리 + 전체 로그인 토큰 폐기, 아이 프로필 삭제 시 프로필·지출 일괄 삭제 처리 | `withdrawUser` + `revokeAllForUser`, `confirmChildProfileDeletion` |
| 독립 보안 검토(MASA) | 아니요(선택 항목) | 미실시 |

## 애매했던 분류 — 결정 요약 (리뷰어 필독)

1. **자녀 정보 → "기타 정보"**: 보호자 입력 콘텐츠로 분류(어린이 대상 앱 아님). §B-5.
2. **엑셀 가져오기 → "파일 및 문서" 수집 예(선택)로 보수적 신고 권장**. §B-6.
3. **해시 IP/User-Agent → 별도 신고 생략, 처리방침에만 기재**. §B-7.
4. **displayName(카카오 닉네임) → "이름"으로 신고**(실명 아닐 수 있으나 이름 항목이 최근접).
5. **광고 없음이되 isSponsored 기능 가동 시 재신고 필요**. §D.
6. **계정 삭제 웹 URL 부재 = 제출 블로커** — 후속 티켓 필수. §A.
